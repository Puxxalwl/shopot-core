# Changelog — shopot-zig

## [неизданное] — API 2.1.0: поиск по истории (SEARCH_MESSAGE / GLOBAL_SEARCH_MESSAGE)

### Added
- **SEARCH_MESSAGE (23) / GLOBAL_SEARCH_MESSAGE (24)** (app/search.zig —
  std-only движок, включён и в exe, и в юнит-корень): payload
  `[cid u32][query str16][limit u32][offset u32]` (global — без cid);
  ответ `[total][count] × {[cid] (global)[flags (бит2 fuzzy)][msg_id][ts]
  [body][entities]}`. Матчинг двухуровневый: точная регистронезависимая
  подстрока (свёртка ASCII + кириллица, новые → старые), затем нечёткий
  слово-уровневый Левенштейн по codepoint'ам (порог max(1, n/3), только
  однословный query). Курсорный offset, лимит как у GET_HISTORY.
  Ошибки: `BAD_ARGS` (пустой query), `TOO_BIG`. `GET_VERSION` → 2.1.0.

## [неизданное] — API 2.2.0: закрепления/удаление чатов, визитки, кэш истории + фикс «отправится позже»

### Fixed
- **Мёртвые сессии не вычищались из `eng.sessions`** (ядро): `onClosed` был
  no-op, поэтому после разрыва TCP автодозвон и линкер считали контакт
  «уже подключённым» и бесконечно пропускали его — сообщения висели в
  очереди «отправится позже», пока собеседник не перезапустит демон.
  Теперь rx-поток при выходе всегда рапортует смерть сессии: `onClosed`
  снимает её с карты (`Engine.retireSession`), контакт уходит в offline,
  автодозвон чинит связь сам. Снятие/закрытие сессий вынесено в retired-
  список, дренируемый тикером без спин-лока (join rx-потока под `app.mu`
  — deadlock).
- **Гонка двойного дозвона при взаимном добавлении**: обе стороны
  одновременно дозванивались, старая сессия оставалась в карте указателем
  на закрытый коннект. `bindSessionLocked` теперь снимает старую сессию
  в retired до биндинга новой (указатель проверяется).
- **Двойной close(2) переиспользованного fd** (net/tcp.zig): `TcpConn`
  получил атомарный флаг `closed`, `closeFd()` идемпотентен.
- **close() из rx-потока сессии = join самого себя** (app/main.zig,
  handleJoinEnvelope): пути отклонения JOIN гасят только транспорт
  (`Session.shutdown()`), rx выходит сам и рапортует `onClosed` один раз.
- **BLOCK_CONTACT**: сессия снимается через retire (без close/join под
  замком) вместо close+remove.

### Added
- **Методы закреплений и удаления чатов** (API 2.2.0): `PIN_CHAT` (25),
  `GET_PINNED_CHAT` (26), `UNPIN_CHAT` (27), `DELETE_CHAT` (28),
  `SEND_CONTACT` (29), `PIN_MESSAGE` (30), `UNPIN_MESSAGE` (31),
  `GET_PINNED_MESSAGES` (32). Закреплённый чат один на демон; закреплений
  ≤ 16 на чат; всё переживает рестарты (записи `.set` с ключами 3–7:
  pin-chat/pin-msg/tombstone по cid-слоту). Удаление чата гасит сессию,
  вычищает outbox/файлы/историю/закрепления; слот контакта остаётся
  надгробием до рестарта (cid стабильны), повторное знакомство создаёт
  новый cid.
- **Конверт CONTACT_CARD (0x43)** (proto/envelope.zig): визитка третьего
  лица — `name str8 ≤ 32, bundle[64], addr str16 ≤ 64`. `SEND_CONTACT`
  пересылает её по живой сессии, получателю приходит событие
  `CONTACT_CARD` (id 12). Старые ядра неизвестный тег отбрасывают.
- **Кэш истории в памяти** (app/main.zig): `hist`/`hist_idx` строятся на
  старте из лога; GET_HISTORY/GET_MESSAGE/SEARCH_MESSAGE/GLOBAL_SEARCH_
  MESSAGE больше не сканируют лог. Кэш мутируется под `app.mu`
  (persistMsg/histDelivered/histPurgeFor), читатели держат тот же лок.

### Changed
- **Бит `delivered` в истории теперь честный**: раньше mine-сообщение
  попадало в лог уже с delivered=1 при записи в сокет; теперь
  delivered=0 до ACK пира — `persistOutboxAck` пишет ack-запись `.outbox`
  и флипает бит в кэше (после рестарта биты восстанавливаются из ack-
  записей). `GET_VERSION` → 2.2.0.
- **DELETE_CHAT не меняет cid живых чатов** до рестарта: удалённые слоты
  скрыты от LIST_CONTACTS/поиска/инвайтов; после рестарта нумерация может
  сдвинуться (клиенты пересинхронизируются на бутстрапе).

## [неизданное] — API 2.1.0: поиск по истории с нечёткими совпадениями

### Added
- **Методы `SEARCH_MESSAGE` (23) / `GLOBAL_SEARCH_MESSAGE` (24)**:
  поиск сообщений по подстроке — в одном чате (payload
  `[cid u32][query str16][limit u32][offset u32]`) или по всем чатам
  сразу (payload без cid, каждая запись ответа начинается с `[cid u32]`).
  Ответ: `[total u32][count u32] × {[flags u8 (bit0 mine, bit1 delivered,
  bit2 fuzzy)][msg_id 16][ts_ms u64][body str16][хвост entities]}`.
  Порядок: сначала точные совпадения (новые → старые), затем нечёткие
  (новые → старые); `offset/limit` (0 → 50, максимум 200 → `TOO_BIG`)
  режут объединённый список, бюджет payload 1 МиБ может урезать `count`
  (`total` — всегда полное число совпадений). Ошибки: `NO_CONTACT`
  (контактный режим), `BAD_ARGS` (пустой query), `TOO_BIG`. Совпадений
  нет — `[total=0][count=0]`, OK. Удалённые чаты (DELETE_CHAT) из поиска
  исчезают: источник — кэш истории под `app.mu`.
- **Регистронезависимый матчинг** (app/search.zig): поточечное UTF-8-
  сравнение со свёрткой регистра — ASCII `A..Z`, кириллица `А..Я` и `Ё/ё`;
  прочие скрипты как есть; некорректный UTF-8 tolerated (байт = codepoint).
  Тело в ответе — в оригинальном регистре. Фразы с пробелами матчатся
  подстрокой целиком.
- **Нечёткий поиск (typo-толерантность)**: для однословного query —
  пословный Левенштейн по codepoint'ам с порогом `max(1, len/3)`
  («превет» находит «привет», «helo» — «hello»); слова выделяются по
  пробельным/пунктуационным байтам. Точное совпадение всегда побеждает
  нечёткое (бит2 = 0); многословный query — только точная подстрока.
  Ограничения v1: simple fold (без `ß→ss`/турецкого i), без фонетики.
- Движок — std-only `app/search.zig` (общий для exe и юнит-тест-корня):
  8 тестов — разбор/валидация payload, регистровые пары ASCII/кириллица,
  пороги Левенштейна, приоритет точного, порядок и окно offset/limit,
  бюджет, глобальный режим с `[cid u32]`. `GET_VERSION` → 2.1.0.

## [неизданное] — fake-TLS v2: побайтовая имитация Chrome + 1 syscall на запись

### Added
- **ClientHello — шаблон реального Chrome 155** (net/faketls.zig): байтовый
  захват из открытого репозитория uTLS (testdata/chrome155_clienthello.hex,
  1955 байт) — 16 шифров, 19 расширений (кейшеры X25519MLKEM768 1216 Б +
  x25519 32 Б, ECH-grease 218 Б, trust_anchors 28 ID, ALPS, ALPN
  h2/http1.1, compress_certificate). На соединение рандомизируются: random,
  session_id, GREASE-поинты (6 позиций, 16 канонических значений), кейшеры,
  ECH-шум, SNI (список расширен до 12 доменов) и **порядок средних
  расширений** (Fisher-Yates между GREASE-границами — как BoringSSL).
- **Клиентский CCS + Finished**: после ClientHello идут ChangeCipherSpec и
  «зашифрованная» запись Finished (52 = 36+16) — направление client→server
  побайтово совпадает с настоящим Chrome.
- **Полный серверный флайт**: ServerHello (AES-128-GCM, кейшер x25519,
  **echo session_id клиента**) + CCS + 4 «зашифрованные» записи EE/Cert/CV/
  Finished правдоподобных размеров (Cert 1200–3600 случайно) — как настоящий
  TLS 1.3-сервер, а не одна запись.
- **AECD-квантование записей данных**: len = payload + 16 (псевдо-тег GCM),
  максимум 16400 — в точности как настоящие записи TLS 1.3; чтение
  отбрасывает тег, границы 17..16400.
- **close_notify**: запись 18 байт `[01 00][16 шума]` перед TCP FIN; пир
  трактует как `Closed` (EOF-семантика). Payload `[01 00]` зарезервирован
  (минимальный obf-кадр 128, m1-заголовок `[40 00]` — коллизий нет).
- **Релейный фрейминг AECD-правдоподобен** (net/relay.zig): маркер-запись
  len 48 (32 + 16 шума), сигнал спаривания len 18 (1 + 17 шума) — вместо
  невозможной в TLS 1.3 записи len 1. Шум = HMAC(marker, метка+наносекунды):
  без глобального состояния и CSPRNG-syscall.
- Тесты: разбор собственного ClientHello независимым парсером (18+1
  расширений, набор типов = захвату, GREASE ∈ канонического множества,
  кейшеры 1216/32, SNI из списка), перестановка порядка расширений,
  sid-echo на проводе, границы/типы битых записей, close_notify, e2e через
  настоящий TCP (rx-поток + tx, эхо 64 КБ), счётчик writeAll (1 вызов на
  TLS-запись).

### Changed
- **Совместимость провода faketls**: обрамление v2 (теги записей, CCS/Fin у
  клиента, флайт из 4 записей у сервера, релейные записи 48/18) несовместимо
  с faketls первого поколения — обе стороны одного релиза ядра (прецедент:
  sealed frames/epoch, PROTOCOL §19). Легаси-фолбэк отклонён: на уровне
  записей маркер версии не детектится надёжно.
- **Скорость записи**: каждая TLS-запись (заголовок+payload+тег) собирается
  в стейджинг-буфере и уходит **одним** writeAll — вдвое меньше syscall на
  запись; косметический шум (теги/GREASE/флайт/перестановка) — быстрый
  PRNG per-connection (DefaultPrng, seed от CSPRNG), io.random — только
  random/session_id (2 вызова на соединение). rbuf+wbuf — одна аллокация
  (~33 КБ на соединение), ноль аллокаций на кадр.
- Модульная документация faketls переписана; PROTOCOL §16 (en/ru) — полное
  описание v2; строка «on-path DPI» в §18 уточнена.

## [неизданное] — форматирование сообщений: entities (offset, kind, value)

### Added
- **TEXT (0x10) несёт entities форматирования** (стиль Telegram
  MessageEntity): после body — хвост `[ent_count u8 ≤ 32]`
  × `[kind u8][offset u16][len u16][value_len u8][value]`. Виды:
  bold / italic / underline / strikethrough / spoiler / code / pre
  (value = язык) / link (value = URL). offset/len — БАЙТЫ UTF-8 в body;
  пересечения диапазонов разрешены, сортировка по offset обязательна.
- **Одна каноническая кодировка хвоста на всех слоях**: провод TEXT,
  записи лога kind msg/outbox, payload API (SEND_MESSAGE, GET_HISTORY,
  GET_MESSAGE, событие MESSAGE_RECEIVED).
- Хелперы proto: `TextEntity`, `EntityKind`, `validateEntities`,
  `encodeEntitiesTail`, `parseEntities` (нулевые аллокации; value —
  срезы входного буфера).

### Changed
- **Провода v4**: байт счётчика entities есть ВСЕГДА — раскладка TEXT
  несовместима со старой. Домен рукопожатия поднят `shopot-hs-v3` →
  `shopot-hs-v4`: ядра разных версий не сходятся вовсе (боксы m2/m3 не
  открываются) — fail-fast вместо молчаливой потери TEXT.
- **API 1.0.0 → 2.0.0 (Major)**: SEND_MESSAGE требует хвост (старый
  payload без него → BAD_FRAME); ответы GET_HISTORY/GET_MESSAGE и
  событие MESSAGE_RECEIVED несут хвост после body. Строгий разбор
  сохранён.
- `Engine.sendText(cid, body, ents)` + `Events.onText(..., ents)`:
  entities валидируются движком (BadEntities), пробрасываются в app-слой.
- `OutboxEntry` хранит хвост готовыми wire-байтами (`ents_tail`):
  офлайн-доставка и рестарт демона сохраняют форматирование без
  перепарса.
- GET_HISTORY: окно режется не только `limit`, но и бюджетом payload
  1 МиБ (entity-тяжёлая история — count может быть меньше limit).

### Compatibility
- Хранилище: заголовок остаётся version 3 — хвост в записях msg/outbox
  аддитивен, читается толерантно; старые записи = «без форматирования»,
  история переживает апгрейд без миграции.
- Ядра v3 ↔ v4 не поднимают сессию (домен рукопожатия). Официальный
  GUI-клиент обязан обновиться на API 2.0.0.

### Tests
- proto: roundtrip entities, точная раскладка хвоста, максимум 32 × 255
  с телом 4096 (один obf-кадр 16384), ошибки parse/validate (границы,
  сортировка, value-правила, неизвестный kind, мусор, обрезание), v3-кадр
  без хвоста → Truncated.
- engine: outbox хранит хвост дословно; onText получает типизированные
  entities; кривые entities → BadEntities.
- session: sealed roundtrip TEXT с entities через rxLoop.
- integration E2E: офлайн-отправка с entities → очередь → флеш → приём
  (хвост дошёл теми же байтами); link с URL онлайн.

## [неизданное] — zlib-сжатие payload sealed-кадров (ROADMAP P1)

### Changed
- **Sealed-заголовок 11 → 12 байт**: `[0xA1][epoch u16][counter u64]
  [comp u8][box]` — байт-флаг сжатия входит в AD AEAD (подделка флага
  невозможна без ключа). Провода несовместим со старыми ядрами до эпох —
  обе стороны обязаны быть на этой версии (как и с RATCHET_KEY).
- **sendSealedTexts**: payload ≥ 512 байт сжимается zlib (std.compress.flate,
  уровень 6) ДО запечатывания. Отказ от сжатия: payload ниже порога,
  уже-сжатое (магии PNG/JPEG/GZIP/ZIP/ZSTD), выигрыш < 64 байт.
- **rxSealed**: после AEAD-open при comp=1 разжимает zlib; разжатое больше
  `max_encoded_len` — кадр отбрасывается (guard от zip-бомб).

### Why
Текст (UTF-8, 2-4x) и длинные истории жмутся в разы меньше по obf-кадрам
(паддинг до бакета тоже сжимается); RTP-аудио не тронуто — у него свои
per-call ключи и DTX.

### Tests
- session: roundtrip сжатия (текст 3.5 КБ жмётся 2x+), порог, магии
  уже-сжатых форматов, zip-бомба (вдвое меньший буфер — отказ), битый
  zlib-поток — отказ.
- integration E2E: обмен текстом 3000 байт через весь стек (compress →
  seal → obf → pipe → open → decompress → decode) в обе стороны.

## [неизданное] — релей-присутствие контакта (реконнект без инвайта)

ROADMAP P0-остаток «постоянное релей-присутствие». Дизайн сверен с
практиками: pre-message ss из Noise KK (статик-статик DH) для парного
секрета; резервация слота как в circuit-relay v2 (libp2p), но без
вуучеров — слот живёт, пока жив коннект.

### Added
- **identity.pairSecret** (crypto/identity.zig): X25519(мой статический
  enc-секрет, enc-паблик пира) — долгосрочный парный секрет, обе стороны
  выводят одинаково без обмена. Компромисция статики раскрывает marker —
  но компромисция identity и так game-over.
- **relay.presenceMarker / dialMarker** (net/relay.zig): marker
  `HMAC(pair_secret, "shopot-relay-presence-v1")` — домен отделён от
  инвайт-marker-а.
- **Слот релея переживает пару**: регистрация держится, пока активна пара
  (лишние коннекты закрываются — слот нельзя занять), по завершении пары
  слот СВОБОДИТСЯ — перерегистрация и повторное спаривание без нового
  инвайта. Заодно исправлено двойное закрытие fd двумя потоками сплита.
- **presence-цикл в приложении** (app/main.zig): relayPresenceLoop — пока
  контакт жив/не заблокирован и нет живой сессии, держит слот контакт-
  маркером; пир появляется — спаривание и новая сессия. Роль рукопожатия
  детерминирована порядком bundle. Старт: после JOIN (relay-инвайт) с обеих
  сторон, при загрузке лога контактов, при разблокировке. Relay-адрес
  пишется в шифрованный лог контактов (хвост [rlen][rhost][rport]),
  переживает рестарт демона.
- **tcp.TcpConn.close: shutdown перед close** — заблокированный в read()
  rx-поток просыпается по EOF (Linux: close(fd) поток НЕ будит — раньше
  локальное закрытие сессии могло вешать join rx-потока).
- serve(…, stop) — флаг остановки релея для тестов.

### Tests
- identity: pairSecret симметричен, зависит от пары.
- relay: presenceMarker детерминирован, домен отделён от инвайта.
- integration E2E (реальный TCP loopback): два ПОЛНЫХ цикла спаривания
  по контакт-маркеру (dial → handshake → тексты в обе стороны → разрыв →
  повторный dial без нового инвайта), лишний коннект при активной паре
  закрывается.

## [неизданное] — докачка файлов (FILE_ACK, окно передачи)

ROADMAP P1 «передача файлов: докачка». Машина состояний отправителя
переехала в движок (как outbox для TEXT): приложение больше не держит
свои TxFile-структуры.

### Added
- **Конверт FILE_ACK (0x62)** `{file_id[16], got u32}` (proto/envelope.zig):
  точка докачки — сколько чанков файла уже у приёмника.
- **Окно передачи в движке** (core/engine.zig): sendFile ставит файл в
  очередь file_tx (байты живут в движке до подтверждения всех чанков —
  как outbox), качает окно 64 неподтверждённых чанков (~1 МБ), окно
  двигается по FILE_ACK каждые 8 чанков. Сессии нет — передача ждёт её,
  реконнект возобновляет с last_ack (resumeFileTx из bindSession).
  Капа 8 одновременных передач (TooManyFiles), идемпотентность по
  (cid, file_id). Завершение — событие onFileSent.
- **Событие UDS FILE_SENT (11)** (app/api.zig): [cid u32][file_id 16]
  [size u32][name str16] — все чанки подтверждены приёмником.
- **Позиционные подтверждения приёмника** (app/main.zig): ответ FILE_ACK
  на КАЖДЫЙ FILE_META (0 — свежий приём, total — файл уже в кэше:
  короткое замыкание докачки), ACK каждые 8 чанков + финальный,
  ACK 0 при несовпадении SHA (сброс приёма — отправитель заново).

### Changed
- **sendFile владеет передачей, а не приложение**: apiSendFile больше не
  строит TxFile/насос в app — движок сам анонсирует META, качает окно и
  переживает реконнекты. Ответ UDS sendfile не изменился
  ([file_id 16][size u32][chunks u32]).
- Файлы без живой сессии теперь СТАВЯТСЯ В ОЧЕРЕДЬ (раньше — отказ
  NoSession): как TEXT-outbox, уйдут при появлении сессии.

## [неизданное] — PCS-ротация рэтчета (DH-шаг в сессии, эпохи)

ROADMAP P0+ «крипта: PCS-ротация рэтчета». Схема — по Double Ratchet
(DH-шаг) с упрощением до совместного обмена свежими пабликами (spec
signal.org §3.1/§3.5; сверка с практиками Signal — fresh DH на ротацию).

### Security
- **PCS-ротация включена в сессию** (core/session.zig, crypto/ratchet.zig):
  каждые rotate_every (256) отправленных сообщений стороны генерируют
  СВЕЖИЕ X25519-пары и обмениваются пабликами конвертом RATCHET_KEY (0x44,
  proto/envelope.zig); обе делают dhStep — цепочки пересоздаются из
  DH(a_fresh, b_fresh), эпоха +1. Раньше dhStep существовал только в API и
  тестах: «DH-шаг каждые 256 сообщений» из старого PROTOCOL никогда не
  выполнялся. Теперь компрометация цепочек эпохи N не читает эпоху N+1
  без нового рукопожатия.
- **Защита кадров «в полёте» при ротации**: sealed-кадр несёт эпоху
  ([0xA1][epoch u16][counter u64][box], AD = заголовок целиком); приёмник
  хранит снапшот приёмной цепочки ПРЕДЫДУЩЕЙ эпохи (prev_recv) и расшифровывает
  опоздавшие кадры пира по нему, счётчик строго продолжает
  последовательность; первый успешный кадр новой эпохи гасит снапшот.
  Вырожденный dh_pub пира — закрытие сессии (протокол-нарушение).
- **Обнуление секретов ротации**: свежие секреты X25519 и снапшоты цепочек
  стираются secureZero сразу после dhStep/гашения снапшота.

### Changed
- **Не совместимо с прежним проводом**: sealed-кадр получил байт эпохи
  (заголовок 9 → 11 байт) и новый конверт RATCHET_KEY 0x44 — версии ядра
  обязаны совпадать (практика репозитория: несовместимые изменения до 1.0
  без бампа версии провода).
- handleRatchetKeyLocked вызывается из rx-потока под send_mu: RATCHET_KEY
  съедается сессией, до движка не доходит (engine.dispatch — пустая ветка
  для exhaustiveness).

### Tests
- ratchet: dhStep инкрементирует эпоху зеркально у обеих сторон.
- envelope: RATCHET_KEY roundtrip, LE-раскладка, обрезанный/хвост.
- session: полный сценарий ротации на ScriptConn — обмен ключами, кадры
  «в полёте» прошлой эпохи по снапшоту, кадры новой эпохи, гашение снапшота.
- integration E2E: 48 сообщений при пороге ротации 4 — многократные
  ротации, ни одно сообщение не теряется, эпохи сторон равны, обмен жив
  после ротации.

## [неизданное] — крипто-фиксы, коалесценция конвертов, запись одним кадром

Ревизия по внешним практикам: Double Ratchet spec (signal.org, §3.5/§8.10),
noise-libp2p (проверка remote static после XX), Zig std.crypto 0.17.

### Security
- **Баг: рассинхронизация рэтчета на битом кадре** (core/session.zig): stepRecv
  сдвигал цепочку приёма ДО расшифровки — один битый sealed-кадр навсегда
  ломал приём TEXT (все последующие сообщения молча терялись). Теперь
  peekRecv выводит ключ под ожидаемый счётчик без сдвига, commitRecv сдвигает
  цепочку только после успешного open (spec §3.5); счётчик из кадра обязан
  совпасть с ожидаемым — повтор sealed-кадра отбрасывается. Регрессионные
  тесты: битый кадр + валидный, повтор кадра.
- **Баг: слой рэтчета не задействовался в продакшене**: engine.sendText и
  flushOutbox шли голым sendEnvelope (только транспортный AEAD) — «двойное
  шифрование» из README/PROTOCOL фактически не работало. Теперь движок шлёт
  TEXT через sendSealedText (msg_id/ts_ms из движка: дедуп/ACK/история
  согласованы), outbox при реконнекте — пачками sendSealedTexts.
- **Привязка статики к личности** (crypto/handshake.zig): статический ключ
  X25519 из бокса m2/m3 сверяется с enc_pk известного bundle (ошибка
  KeyMismatch). Сигнатура ответчика покрывает транскрипт ДО бокса — без
  сверки ключи могли выводиться с чужой статикой (практика noise-libp2p:
  remote static проверяет приложение). Session.establish теперь принимает
  peer_bundle целиком.
- **Ed25519-пара кэшируется в Identity** (crypto/identity.zig): каждая
  подпись раньше тянула generateDeterministic (SHA-512 + скалярный вывод);
  now подпись = одна операция sign. Рукопожатия и JOIN ускорились, ключи
  обнуляются в deinit как раньше.

### Performance / сеть
- **Заголовок кадра + payload одним writeAll** (core/session.zig): раньше
  [len u16] писался ОТДЕЛЬНЫМ writeAll — на обф-слое каждый конверт порождал
  ДВА кадра (2 байта заголовка раздувались в кадр 128), т.е. +128 байт на
  проводе и +1 syscall на каждое сообщение. Теперь один obf-кадр.
- **Коалесценция мелких конвертов** (ROADMAP P1): sendSealedTexts запечатывает
  пачку и кладёт [len][sealed]||… одним writeAll — приёмник разбирает поток
  leftover-буфером ObfReader, формат провода не меняется. flushOutbox шлёт
  пачками по 64: оверхед 128+26 байт на сообщение → на пачку.

### Docs
- PROTOCOL.md: приём рэтчета (peek/commit), сверка статики, DH-шаг честно
  помечен как неподключённый (плановая PCS-ротация, ROADMAP).
- SECURITY.md: инвентарь приведён к реальности (std.crypto вместо
  устаревшего libsodium/XSalsa20, ChaCha20-Poly1305).

## [неизданное] — звонки, TUI, инвайты, LAN-автолинк

### Криптослой
- **Изменение протокола (несовместимо): m1 теперь 64 байта** — e1_pub (32) ||
  enc_pk инициатора (32). По enc_pk респондент находит контакт ДО расшифровки

  u16, предельный класс исключён; скретч-буфер читателя вдвое меньше.
- Хранилище: nonce записи лога детерминированный [0 x4][epoch u32][seq u32]
  (поле на диске сохранено, старые записи читаются как раньше) — ноль
  энтропии на запись, повтора (key, nonce) не бывает.
- Звонки: guard на переполнение seq u32 кадра CALL_AUDIO (обрыв до повтора
  ключа/nonce, практически недостижимо).

### Приложение
- Зашифрованные звонки: offer/accept/reject/hangup, кадры 8 кГц моно i16
  по 20 мс; аудио через fifos ~/.shopot/pcm/{mic,spk} (arecord/aplay), шифр
  кадра — HKDF(secret, seq) + AEAD. Тишина не шлётся (мик-loop пропускает
  пустые кадры — трафик только от реального звука).
- TUI: полноэкранный ANSI-интерфейс — двухпанельный (список чатов с online-точкой
  и возрастом последнего пакета, лента с таймстампами, строка ввода, панель
  подсказок). REPL сохранён для не-терминала/скриптов.
- TUI-клавиши: буквы — всегда текст; горячие — Alt+буква (Alt+c звонок,
  Alt+a принять, Alt+h сброс, Alt+b блок, Alt+q выход), команды — префикс /;
  кадр перезаписывается с ESC[H, ввод разбирается из буфера (вставка не
  теряет байты).
- Юнит-тесты всех модулей реально бегают: тестовый корень src/shopot_tests.zig
  (раньше zig build test собирал только 4 теста, 87 модульных молча не
  собирались); heartbeat-тесты приведены к backoff-таймлайнам, tick молчит
  после offline.
- Инвайт-коды shopot1.<b64(bundle||name[@host:port])>: add <код> — одна
  команда вместо обмена hex-id и connect.
- LAN-автолинк: UDP-мультикаст 239.77.77.77:57770, анонс 74 байт каждые 2 с;
  обе стороны уже в контактах — TCP-соединение поднимается само (инициатор —
  сторона с меньшим bundle, детерминизм без гонки). Авто-прослушка TCP 7777-7786.
- Онлайн-статус: пинги ТОЛЬКО после 4 с тишины с экспоненциальным
  замедлением (5с→10→20→40→60с), TCP keepalive 30с/10с/3 — ноль периодических
  запросов при активном трафике.

## [неизданное] — интерактивный чат и TCP-транспорт

### Added
- **net/tcp.zig**: блокирующий TCP-транспорт на сырых POSIX-сокетах
  (socket/connect/bind/listen/accept4/read/write через std.os.linux),
  адаптер к core-интерфейсу Conn. Намеренно без std.Io: один вызов —
  один syscall, предсказуемое поведение при потоках CLI. IPv4-литералы
  адресов, SO_REUSEADDR для быстрых перезапусков. Файл из скоупа net,
  написан лидом (net-агент неактивен).
- **app/main.zig**: интерактивный REPL `chat` — add/contacts/listen/
  connect/msg/react/block/unblock/quit; поток accept-лупа и поток
  presence-тикера (250 мс, heartbeat-пинги); спин-блокировки на
  атомарном флаге вместо std.Io.Mutex (дедлок кросс-поточного Io).
  Контакты и блокировки сохраняются в AEAD-лог при каждом изменении.


## [zig-core 0.1.0] — 2025-10-14

Первый релиз полностью переписанного ядра на Zig 0.17.0. Только std,
ноль сторонних пакетов, ноль OS-зависимостей: пользователь ставит только
сам Zig.

### Added
- **crypto/** (7 модулей): identity (X25519+Ed25519 из сида, HKDF `shopot-id-v3`),
  handshake (XX-подобный, BLAKE2s-транскрипт, Ed25519-подписи, wire 32/144/112),
  aead (ChaCha20-Poly1305, счётчикные nonce), kdf (HKDF-SHA256, вектор RFC 5869),
  ratchet (симметричные chain'и + dhStep с детерминированным тай-брейком),
  call_keys (ключ кадра звонка = HKDF `shopot-call-v3` || seq), pad
  (квантование размеров 128..65536).
- **proto/**: codec — безаллокационные LE Reader/Writer; envelope — бинарные
  конверты v3 (TEXT/REACT/BLOCK_NOTICE/PING/PONG/CALL_SIGNAL/CALL_AUDIO),
  строгий decode, никаких JSON/varint.
- **net/**: framing ([u16][payload]); obfuscate — ChaCha20-Poly1305 поверх
  транспорта, длина кадра на проводе всегда равна классу бакета, ни одного
  постоянного байта (анти-DPI маскировка); heartbeat — миллисекундная
  presence-машина без потоков и опросов.
- **store/**: append-only AEAD-лог (ChaCha20-Poly1305 + HKDF сида),
  индекс, tombstone, компакция с атомарным rename. SQLite больше не нужен.
- **core/**: vtable-интерфейсы Conn/Transport/Clock (DI вместо модулей),
  session (рукопожатие + двойное шифрование TEXT: рэтчет поверх
  обфусцированного AEAD-потока), engine (контакты, блокировки, реакции,
  dispatch, звонки).
- **app/**: CLI `init`/`id` (сид 0600 в ~/.shopot/zig-seed).
- **tests/integration.zig**: полный стек в памяти — два движка, рукопожатие,
 sealed TEXT в обе стороны, реакции, presence. Без сети и реального времени.
- **CI**: `.github/workflows/release-zig.yml` — теги `zig-v*` собирают
  x86_64-linux и aarch64-macos ReleaseFast-тарболлы.

### Security
- Двойное шифрование сообщений и звонков (транспортный AEAD + свой ключ
  на слой; кадр звонка — одноразовый ключ на seq).
- Хранилище не содержит ни одного байта открытого текста.
- Компрометация транспортного ключа не раскрывает историю сообщений.

### Notes
- Обфускация скрывает содержимое и форму трафика от DPI-белых списков
  (квантованные длины, случайные байты, отсутствие магических чисел),
  но не является анонимностью против глобального пассивного наблюдателя.
