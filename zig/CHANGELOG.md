# Changelog — shopot-zig

## [неизданное] — UDS-апи как единственный интерфейс + история сообщений

### Удалён интерактивный CLI
- REPL/TUI (chat) удалены: демон serve-only. Команды живут только в UDS-апи,
  естественный путь для сторонних клиентов. docs/CORE-API.md — спецификация.

### API: история и реакции
- **gethistory <cid> [n]** — последние N сообщений переписки (kind MSG в логе:
  [cid][flags][msg_id][ts][len][body], ts — локальное wall clock).
- **getmessage <msg_id_hex>** — одно сообщение по идентификатору.
- **REACT: code u8 → u32 unicode code point** (провода u32 LE, U+2764 = ❤).
  Ввод в API: десятичное / 0x… / U+… / сам глиф. Событие реагирования —
  машиночитаемое: sys <cid> react <msg_id_hex> <codepoint>.
- msg отвечает msg_id (hex32) — по нему реакции и статусы.

## [неизданное] — доставка офлайн-сообщений (T2)

### Outbox + ACK + дедуп
- **TEXT без сессии больше не ошибка**: сообщение уходит в outbox
  (sendText возвращает queued), ядро доставит при появлении контакта.
- **Конверт ACK 0x15** (msg_id): получатель подтверждает каждый TEXT;
  отправителю — событие «доставлено» (REPL/UDS), запись гасится.
- Дедуп входящих: окно 64 msg_id на контакт, повтор после реконнекта
  отбрасывается, доставка идемпотентна.
- Персистентность: kind OUTBOX в шифрованном логе (добавление/погашение),
  очередь переживает перезапуск демона. Контакт из JOIN пишется в лог
  (раньше терялся при рестарте).

### Автодозвон и presence-события
- Автодозвон офлайн-контактов по последнему известному адресу (код с
  @host:port или LAN-анонс): backoff 1с → 60с с джиттером.
- Первый мультикаст-анонс — строго при старте демона (пир с очередью
  узнаёт о возврате за ~RTT). Адрес из анонса запоминается в контакте.
- contacts помечает очередь [в очереди].

## [неизданное] — односторонние приглашения (T1), чистка C++-моста

### Односторонние приглашения (invite v2 + JOIN)
- **Правило одного действия**: приглашённый выполняет РОВНО один `add <код>`
  — контакт, сессия и контакт у приглашающего поднимаются ядром сами.
- Код `shopot://i/<b64url(bundle|secret16|имя)>[@host:port]`: секрет одноразовый,
  реестр до 4 приглашений в памяти приглашающего. v1-коды (`shopot1.`) читаются
  для совместимости (взаимный add).
- **Конверт JOIN 0x40** = bundle[64] + name[u8 ≤ 32] + sig[64] + hmac[32]:
  sig (Ed25519 над transcript) привязывает bundle к ключам сессии, hmac
  (HMAC-SHA256 по invite_secret) доказывает держателя кода. Первый конверт
  после рукопожатия, отправляется ядром автоматически.
- Респондер с живым приглашением принимает m1 от неизвестного enc_pk как
  pending-сессию (establishPending: sig в m3 не проверяется), окно 3 с,
  затем JOIN-проверка: валид — контакт добавлен и сессия забиндена;
  невалид/таймаут — close.
- LAN-захват: держатель кода без адреса дозванивается до анонса приглашающего
  (linkerLoop инициирует всегда, независимо от порядка бандлов).

### Чистка (реверс C++-CLI направления)
- cpp-cli/ (вендореный MessagingApp) удалён; TCP-мост 7788/7789 из cli_server.zig
  удалён. CLI-апи — только UDS: фокус на ядро + апи для сторонних клиентов.
- Makefile: build/test/run/clean; docs: секции про C++-мост сняты.

## [неизданное] — CLI-апи (UDS) + C++-клиент без правок

### CLI-фронт-енды поверх одного ядра
- **UDS-апи** `$HOME/.shopot/api.sock`: построчные команды REPL
  (msg/call/answer/hangup/block/contacts/invite/add), голый текст — сообщение
  в выбранный чат, события — строками `msg/sys/presence <cid> ...`.
  `serve` — новый подрежим: демон без локального ввода, только CLI-апи.
- **Мост для C++-клиента**: вендорен MessagingApp (Bahaaio/MessagingApp,
  Apache-2.0, cpp-cli/, НЕ модифицирован; библиотека Terminal++ — пин
  сабмодуля b151521b) и собирается `make cli` системным g++. Демон
  импersonирует его сервер на 127.0.0.1:7788: кадры `name,text`, команды
  ядра — `!`-префиксом (клиент глотает неизвестные `/`), события — тем же
  форматом. Звонки и блокировка доступны из немодифицированного клиента.

### Починки
- invite: паника индекса при длинном имени+адресе (b64-буфер 112 < 130);
  канонический размер кода bundle+1+имя (мусорный хвост raw не кодируется,
  коды на ~40% короче); decode принимает 66..97 байт.
- add по инвайт-коду с адресом: порт терялся (addr() без порта) — теперь
  собирается host:port, автоподключение работает напрямую, не только через
  LAN-автолинк.
- TUI: колонка автора фикс. ширины и в своих сообщениях (текст ленты
  выровнен), хинт-бар сокращён.

## [неизданное] — звонки, TUI, инвайты, LAN-автолинк

### Криптослой
- **Изменение протокола (несовместимо): m1 теперь 64 байта** — e1_pub (32) ||
  enc_pk инициатора (32). По enc_pk респондент находит контакт ДО расшифровки
  (раньше требовался peer_sign_pk заранее). Транскрипт покрывает весь m1.
- Секрет звонка: HKDF-expand(transcript, call_id||"shopot-call-secret").
- establishIdentified(): рукопожатие со стороны респондента по identify-колбэку.
- **Изменение провода (несовместимо): obf-кадр = [wirelen u16][seq u64 LE][box]** —
  nonce12 = 0000||seq из счётчика кадров направления вместо случайного nonce8:
  повтора пары (key, nonce) не бывает по построению, строгая проверка seq на
  приёме отбрасывает повтор/перестановку/подмену кадра. AAD = [wirelen][seq].
- **Убран класс кадров 65536** (таблица 128..16384): длина кадра на проводе —
  u16, предельный класс исключён; скретч-буфер читателя вдвое меньше.
- Хранилище: nonce записи лога детерминированный [0 x4][epoch u32][seq u32]
  (поле на диске сохранено, старые записи читаются как раньше) — ноль
  энтропии на запись, повтора (key, nonce) не бывает.
- Звонки: guard на переполнение seq u32 кадра CALL_AUDIO (обрыв до повтора
  ключа/nonce, практически недостижимо).

### Приложение
- Зашифрованные звонки: offer/accept/reject/hangup, кадры 8 кГц моно i16
  по 20 мс; аудио через fifos ~/.shopot/pcm/{mic,spk} (arecord/aplay), шифр
  кадра — HKDF(secret, seq) + AEAD. Тишина не шлётся (мик-loop пропускает
  пустые кадры — трафик только от реального звука).
- TUI: полноэкранный ANSI-интерфейс — двухпанельный (список чатов с online-точкой
  и возрастом последнего пакета, лента с таймстампами, строка ввода, панель
  подсказок). REPL сохранён для не-терминала/скриптов.
- TUI-клавиши: буквы — всегда текст; горячие — Alt+буква (Alt+c звонок,
  Alt+a принять, Alt+h сброс, Alt+b блок, Alt+q выход), команды — префикс /;
  кадр перезаписывается с ESC[H, ввод разбирается из буфера (вставка не
  теряет байты).
- Юнит-тесты всех модулей реально бегают: тестовый корень src/shopot_tests.zig
  (раньше zig build test собирал только 4 теста, 87 модульных молча не
  собирались); heartbeat-тесты приведены к backoff-таймлайнам, tick молчит
  после offline.
- Инвайт-коды shopot1.<b64(bundle||name[@host:port])>: add <код> — одна
  команда вместо обмена hex-id и connect.
- LAN-автолинк: UDP-мультикаст 239.77.77.77:57770, анонс 74 байт каждые 2 с;
  обе стороны уже в контактах — TCP-соединение поднимается само (инициатор —
  сторона с меньшим bundle, детерминизм без гонки). Авто-прослушка TCP 7777-7786.
- Онлайн-статус: пинги ТОЛЬКО после 4 с тишины с экспоненциальным
  замедлением (5с→10→20→40→60с), TCP keepalive 30с/10с/3 — ноль периодических
  запросов при активном трафике.
- Устранён самодедлок колбэков звонка (события приходят уже под локом App).

## [неизданное] — интерактивный чат и TCP-транспорт

### Added
- **net/tcp.zig**: блокирующий TCP-транспорт на сырых POSIX-сокетах
  (socket/connect/bind/listen/accept4/read/write через std.os.linux),
  адаптер к core-интерфейсу Conn. Намеренно без std.Io: один вызов —
  один syscall, предсказуемое поведение при потоках CLI. IPv4-литералы
  адресов, SO_REUSEADDR для быстрых перезапусков. Файл из скоупа net,
  написан лидом (net-агент неактивен).
- **app/main.zig**: интерактивный REPL `chat` — add/contacts/listen/
  connect/msg/react/block/unblock/quit; поток accept-лупа и поток
  presence-тикера (250 мс, heartbeat-пинги); спин-блокировки на
  атомарном флаге вместо std.Io.Mutex (дедлок кросс-поточного Io).
  Контакты и блокировки сохраняются в AEAD-лог при каждом изменении.


## [zig-core 0.1.0] — 2025-10-14

Первый релиз полностью переписанного ядра на Zig 0.17.0. Только std,
ноль сторонних пакетов, ноль OS-зависимостей: пользователь ставит только
сам Zig.

### Added
- **crypto/** (7 модулей): identity (X25519+Ed25519 из сида, HKDF `shopot-id-v3`),
  handshake (XX-подобный, BLAKE2s-транскрипт, Ed25519-подписи, wire 32/144/112),
  aead (ChaCha20-Poly1305, счётчикные nonce), kdf (HKDF-SHA256, вектор RFC 5869),
  ratchet (симметричные chain'и + dhStep с детерминированным тай-брейком),
  call_keys (ключ кадра звонка = HKDF `shopot-call-v3` || seq), pad
  (квантование размеров 128..65536).
- **proto/**: codec — безаллокационные LE Reader/Writer; envelope — бинарные
  конверты v3 (TEXT/REACT/BLOCK_NOTICE/PING/PONG/CALL_SIGNAL/CALL_AUDIO),
  строгий decode, никаких JSON/varint.
- **net/**: framing ([u16][payload]); obfuscate — ChaCha20-Poly1305 поверх
  транспорта, длина кадра на проводе всегда равна классу бакета, ни одного
  постоянного байта (анти-DPI маскировка); heartbeat — миллисекундная
  presence-машина без потоков и опросов.
- **store/**: append-only AEAD-лог (ChaCha20-Poly1305 + HKDF сида),
  индекс, tombstone, компакция с атомарным rename. SQLite больше не нужен.
- **core/**: vtable-интерфейсы Conn/Transport/Clock (DI вместо модулей),
  session (рукопожатие + двойное шифрование TEXT: рэтчет поверх
  обфусцированного AEAD-потока), engine (контакты, блокировки, реакции,
  dispatch, звонки).
- **app/**: CLI `init`/`id` (сид 0600 в ~/.shopot/zig-seed).
- **tests/integration.zig**: полный стек в памяти — два движка, рукопожатие,
 sealed TEXT в обе стороны, реакции, presence. Без сети и реального времени.
- **CI**: `.github/workflows/release-zig.yml` — теги `zig-v*` собирают
  x86_64-linux и aarch64-macos ReleaseFast-тарболлы.

### Security
- Двойное шифрование сообщений и звонков (транспортный AEAD + свой ключ
  на слой; кадр звонка — одноразовый ключ на seq).
- Хранилище не содержит ни одного байта открытого текста.
- Компрометация транспортного ключа не раскрывает историю сообщений.

### Notes
- Обфускация скрывает содержимое и форму трафика от DPI-белых списков
  (квантованные длины, случайные байты, отсутствие магических чисел),
  но не является анонимностью против глобального пассивного наблюдателя.
