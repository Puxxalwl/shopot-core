# AGENTS.md — правила для агентов и контрибьюторов

## Железные правила
1. **Toolchain:** Zig 0.17.0. **OS-пакеты запрещены** — пользователь не должен ничего
   ставить через pacman/apt/brew: всё собирается из репозитория. Zig-пакеты разрешены
   (zig build package manager, версия зафиксирована хэшем в build.zig.zon), но каждая
   зависимость — обоснование в CHANGELOG; ядро криптографии держим на std.crypto.
2. **Владение файлами:** агент/человек трогает только файлы своего скоупа (таблица ниже).
   Чужие файлы — только чтение. Интеграция — только у лида.
3. **Память:** каждый публичный вызов принимает `std.mem.Allocator`. Горячие пути —
   `FixedBufferAllocator`/стек, ноль аллокаций на кадр там, где возможно. Глобальное
   состояние запрещено. `usingnamespace` запрещён.
4. **Ошибки:** модульные error set'ы. `catch unreachable` — только в тестах.
   `anyerror` на границах модулей запрещён.
5. **Криптография:** только `std.crypto`. Ключи обнулять `std.crypto.secureZero`.
   Никаких самодельных примитивов — только композиция (AEAD/KDF/HMAC из std).
6. **Формат:** little-endian явно через `std.mem.readInt/writeInt`. Никакого JSON.
   Длина — фиксированные u16/u32, никакого varint в кадрах.
7. **Тесты:** `test {}` блоки в каждом файле + интеграционные в `tests/`.
   `zig build test` зелёный — обязательное условие передачи работы лиду.
8. **Стиль:** `zig fmt` перед коммитом. snake_case файлы, один смысл — один файл.
   Публичный API минимален, документирующие комментарии над каждым `pub`.

## Скоупы
| Агент | Файлы |
|---|---|
| lead | build.zig, src/shopot.zig, src/shopot/core/*, src/shopot/app/*, docs/*, CHANGELOG.md |
| crypto | src/shopot/crypto/*.zig |
| proto | src/shopot/proto/*.zig |

| store | src/shopot/store/*.zig |

## Процесс
- Работа ведётся в `zig/` монорепозитория shopot-core; C++-версия на master не трогается.
- Каждый модуль самодостаточен: не импортирует чужие модули, кроме `core/interfaces.zig`.
- Интеграционные тесты пишет лид; модульные — владелец модуля.
- Коммит: `zig: <модуль>: <суть>`. Ченджлог обязан обновляться при изменении API.
