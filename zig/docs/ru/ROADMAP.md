# ROADMAP — технический план shopot-core

Приоритеты для агентов и авторов клиентов. Всё — std-only: без ОС-пакетов и
внешних сервисов. Порядок = рекомендуемый порядок реализации. Английская
версия: [../ROADMAP.md](../ROADMAP.md).

## P0 — ✅ ГОТОВО

- ~~Релей~~: `shopot relay` + `invite <имя> relay <addr>` — спаривание
  по HMAC-marker-у (секрет инвайта), байтовый сплит, само-переподключение
  A-стороны (e2e: E2E-RELAY-PASS).
- ~~Fake-TLS~~: маскировка провода под TLS 1.3.
- ~~Джиттер-буфер звонка~~: очередь 16 слотов, плейаут тиком 20 мс.
- ~~Звонки 16 кГц + ADPCM + DTX~~: 72 кбит/с.
- ~~Файлы чанками~~: FILE_META/FILE_DATA, SHA-сверка, дедуп.

Оставшееся из P0: ✅ сделано — постоянное релей-присутствие (контакт-секрет,
реконнект без нового инвайта).

## P0+ — ✅ ГОТОВО: PCS-ротация рэтчета

- ~~DH-шаг в сессии~~ ✅: конверт `RATCHET_KEY` (0x44) обменивается свежими
  X25519-пабликами; обе стороны делают `dhStep` каждые `rotate_every = 256`
  сообщений; sealed-кадры несут эпоху
  (`[0xA1][epoch u16][counter u64][box]`); кадры «в полёте» прошлой эпохи
  расшифровываются по снапшоту `prev_recv`, гасятся первым кадром новой
  эпохи. Полное skipped-keys-окно как в spec §2.6 не нужно: порядок потока
  (obf/TCP) гарантирует строго последовательные кадры, дедуп по счётчику.
  E2E: 48 сообщений при пороге 4, ни одно не теряется, эпохи сторон равны.

## P0+ — следующее за релеем

Fake-TLS прячет протокол от DPI, релей прячет IP. Осталось:

- ✅ **Релей-присутствие**: контакт хранит relay-адрес (в шифрованном логе,
  переживает рестарт) и держит регистрацию с
  `marker = HMAC(X25519(мой_статик, паблик_пира), "shopot-relay-presence-v1")`
  — обе стороны выводят его без обмена (pre-message `ss` из Noise KK);
  реконнект после разрыва сессии спаривается через релей без нового
  инвайта (`relayPresenceLoop` в app, роль рукопожатия детерминирована
  порядком bundle). Релей освобождает слот marker-а по завершении пары —
  перерегистрируется любая сторона (E2E: два цикла спаривания на TCP
  loopback).
- **Мульти-релей**: инвайт с несколькими адресами (failover).

## P0 — звонки: качество

- **Джиттер-буфер** (адаптивный, 2–5 кадров): сейчас кадр играет сразу,
  сетевой разброс → щелчки. Буфер в onCallAudioEv + таймер слива.
- **Resume аудио**: DTX уже шлёт keepalive; добавить comfort-noise
  (лёгкий шум при тишине).
- **Opus нельзя** (внешний кодек) — альтернатива: двухуровневый ADPCM
  (высокие частоты вторым блоком) или SBC-подобный суб-кодек, ~14 кбит/с.
  Приоритет ниже: 72 кбит/с уже ок для голоса.
- Громкость/AGC — на клиенте (GUI), ядро не лезет.

## P1 — передача файлов: докачка

- ✅ **FILE_ACK** `{file_id, got u32}`: приём подтверждает каждый 8-й чанк
  (+ финальный и позиционный на каждый FILE_META); отправитель держит окно
  64 чанка (~1 МБ) и докачивает с последнего ACK при разрыве сессии —
  передача возобновляется при реконнекте автоматически (engine.file_tx,
  resumeFileTx + событие UDS FILE_SENT). E2E «докачка после разрыва» в
  tests/integration.zig.
- Список файлов по UDS: `files <cid>` → `f <id_hex> <size> <имя>` (записи
  FILE в логе уже пишутся).
- Выдача содержимого: `getfile <id_hex> <путь>` — копия из кэша.
- Чанк >16000 (до 64000) одним конвертом: меньше кадров на большие файлы
  (obf всё равно режет на 16356-байтные кадры) — сначала замерить выгоду.

## P1 — производительность

- ~~Коалесценция мелких конвертов~~ ✅: заголовок+payload одним writeAll
  (один obf-кадр на конверт вместо двух); пачки outbox/TEXT через
  sendSealedTexts — один кадр на пачку. Дальше по желанию: коалесценция
  REACT/ACK/PROFILE в общий пачечный писатель.
- ✅ **zlib-сжатие** payload ≥ 512 байт до AEAD (std.compress.flate,
  zlib-контейнер, уровень 6): sealed-заголовок получил байт-флаг `comp`
  (12 байт, покрывается AD); текст жмётся 2–4×, уже-сжатое детектится по
  магическим байтам (PNG/JPEG/GZIP/ZIP/ZSTD) и не жмётся, выигрыш < 64 байт
  отбрасывается, декомпрессия ограничена лимитом кадра (guard от zip-бомб).
- FBA на горячих путях envIn/dispatch (AGENTS.md §3): сейчас пара аллокаций
  на конверт. Замерить, потом точечно.

## P2 — удобства API

- `search <запрос>` — поиск по истории (лог MSG уже расшифровывается
  readAll(.msg)).
- Групповые чаты = N двусторонних сессий + fanout движком (без новых
  конвертов, только логика рассылки). Сначала спросить: нужно ли.
- Индикатор `typing`: пустой конверт (тег TBD — 0x62 занят FILE_ACK),
  UDS-событие `typing <cid>` + гашение через 3 с.
- Экспорт истории: `export <cid> <путь>` — текстовый дамп из лога.

## Анти-план (НЕ делать)

- ❌ Внешние зависимости (opus/libsodium/zlib-ng) — только std.
- ❌ JSON на UDS — бинарный кадровый протокол не меняем.
- ❌ «Облачная» синхронизация — serverless-архитектура, ключи только у
  пользователей.
- ❌ Мульти-device: одна личность = один живый инстанс (сейчас так;
  multi-device требует ratchet-форварда — отдельный большой проект).
